Blockbound Handbook

How the game is built, which invariants will bite you, and what to build next. A 2D mining-and-building sandbox in native ES modules — no bundler, no dependencies, no build step.

The target player is a child on an iPad. That single fact explains most of the design: touch-first controls, no keyboard requirement, an aggressive service-worker update path, rendering that degrades rather than showing a blank screen, and a save format that fights for storage quota.

Roughly 11,000 lines of JavaScript. Full source of these docs lives in docs/ARCHITECTURE.md and docs/ROADMAP.md.

The two large files are js/render/index.js (~3,000 lines) and js/session/GameController.js (~1,700). Everything else is small and focused.

02 Layering and the dependency rule

The intended dependency direction is one-way, and one rule holds the whole thing together.

  • core/ — engine constants and pure maths. Imports almost nothing.
  • content/ — the data catalog: blocks, tools, recipes, prefabs, cheats. Adding game content should mostly mean editing these files.
  • Domain modules (world, player, inventory, entities, interact) — rules and state shape.
  • render/ — reads state and draws. Never mutates game state.
  • session/ — owns the single session object and the frame order.
  • main.js — the only file that touches the DOM, and the only owner of the rAF loop.
The rule that matters

Domain and content modules stay free of document, window, and canvas. That is what lets tests/run.mjs import them directly in Node with no browser shim. Break it and the suite loses its ability to test behaviour at all.

03 The world model

Tiles

A world is flat typed arrays of WORLD_W × WORLD_H: tiles, light (both Uint8Array), surface (Int16Array), and biome. WORLD_H is a fixed 128. WORLD_W is mutable, chosen per world:

PresetWidthFeel
Tour1,024~3 min lap
Standard4,096~12 min lap (default)
Vast8,192~25 min lap
Epic16,384Blockheads 1×
Invariant

Anything that captures WORLD_W into a module-level constant at import time is wrong for every world that is not 4,096 wide. Read the live binding, or call getWorldW().

Horizontal wrap

The signature feature: walk far enough and you return to where you started. Every horizontal coordinate goes through wrapX(), every horizontal difference through wrapDeltaX(). A raw a.x - b.x near the seam produces a distance of nearly a whole world — camera, mob AI, drop pickup and reach checks all depend on getting this right.

Vertical bands

y=0            space edge
y=2            SKY_LIMIT — hard build ceiling
y≈36           SURFACE_Y — nominal surface band
   …           caves, ores
y=WORLD_H-8    MAGMA_Y — magma crust caps molten lava
y=WORLD_H-1    bedrock floor

Magma vs Lava is a deliberate two-block design. Magma is a solid, mineable, faintly glowing crust that does not burn. Lava beneath it is a non-solid hazard you sink into and cannot mine. Breaking the crust is a deliberate act with consequences; the route to bedrock is to quench lava with water and mine the stone it leaves.

Lighting and liquids

Light floods with radius LIGHT_RADIUS = 16, which must stay at or above the brightest emitter (lantern, 14). After generation, lighting is column-local — edits mark dirty columns and only those recompute, which is what keeps mining responsive at Epic width.

The liquid sim carries two constraints worth preserving. Levels, not booleans — a binary "is water" spreads without bound and one bucket would flood a flat world. Levels live in a sparse map, not a parallel array — a second full-world Uint8Array would be 2 MB on Epic, in memory and in every save. Only flowing tiles carry an entry, so a settled world stores almost nothing, and an active-cell queue means a still world costs nothing per frame.

04 The session and its frame order

One module-level session holds world, player, inventory, entities, input, ui, camera, stats, time of day, difficulty and pause. gameUpdate(dt) runs a deliberate sequence — the order is load-bearing.

  1. Toast timer, pause handling (Esc closes an open panel before it pauses)
  2. Zoom — wheel delta or iPad pinch absolute
  3. Difficulty-derived flags — godMode, canFly, hazardMul
  4. Panel toggles — craft / bag / creative / chest
  5. applyKidsNav — tap targets become per-frame movement intent
  6. updateSurvival — hunger, energy, regen, death and respawn
  7. updatePlayer — physics, collision, mining and placing
  8. Mining and placing results — drops, gravity, light, milestones
  9. Drops, critters, hostiles
  10. Weather → camera → liquids → autosave
Invariant

When paused, latched one-shot input flags are cleared before the early return. Otherwise they accumulate while paused and all fire at once on resume — press Esc, mash keys, unpause, and the character does all of it at once.

05 Input and the two control modes

Movetap where to walkstick / WASD

Camerafree pan by drag; soft box followlag-follow, player above centre
Keyboardnever requiredsupported

Kids mode routes through systems/nav.js, turning a tap into steering intent plus a queue of mine/place/use jobs the character walks to and performs. The character does the work; a second tap cancels.

The kids camera is a box pull, never a re-centre — children jump and place a block under themselves, and a centring camera yanks the view out from under that. Its vertical dead zone is asymmetric: the downward edge derives from the real HUD height so the character can never settle behind the hotbar.

06 Rendering

Strict back-to-front: sky gradient → sun/moon/stars → clouds → parallax → cave backdrop → seamless terrain (offscreen) → light multiplied on → deferred non-terrain blocks → entities and player → HUD.

  • Every stage is wrapped in try/catch with a flat-colour fallback. On an iPad there is no console to read, and a thrown render error would leave a child staring at a blank screen. main.js installs a DOM error reporter for the same reason.
  • Layout constants are shared, not duplicated. hudLayout.js and chestLayout.js export real pixel geometry so non-render code — the camera, hit-testing — can reason about where the UI actually is.

07 Content catalogs

Adding content should mean editing data, not logic.

  • blocks.js — ids plus BLOCK_META. Flags drive behaviour generically: solid, mine, drops, gravity, fluid, hazard, climb, platform, hang, light, alpha, interact. A new block usually needs an id, a meta row and a texture.
  • tools.js — TOOLS, FOOD, ITEM_NAMES. Note canStack() is !isTool(), so anything in TOOLS does not stack.
  • recipes.js, milestones.js, cheats.js, prefabs.js.

Difficulty is a single profile table, and most mode differences are multipliers rather than branches. Magma burn deliberately reuses mobDamageMul rather than introducing a parallel dial.

08 Persistence and updates

Two tiers, because a single blob hits storage quota: a small library holding global prefs and world metadata, and a heavy per-world payload under blockbound-w-<id>.

There are two service workers on purpose. sw-bb.js is the real one; sw.js is a legacy bridge that exists only to rescue iPads stuck on an old shell.

Invariant

GAME_VERSION appears in seven places that must move together: core/constants.js, the sw-bb.js cache name, the manifest start_url, two index.html query strings plus its BUILD var, and two in update.html. Bump them all, or the update path silently stops working.

09 Testing

node tests/run.mjs — a dependency-free runner with a single ok(cond, msg) helper, mixing structure checks, source assertions that pin a specific regression, and behavioural tests driving real modules with stub worlds.

Many tests are named for the bug they pin. When fixing a regression, add the test that fails before the fix and passes after — and verify that it actually fails, or it is decoration.

11 Roadmap — architecture

A menu, not a plan. Nothing here is committed.

Split render/index.js first

Three thousand lines holding sky, terrain, lighting, entities, HUD, panels and hit-testing. Natural seams already exist: sky.js, terrain.js, blocks.js, entities.js, hud.js, panels/. Low risk — it is drawing code with no state — and high payoff for every future visual change.

Split session/GameController.js

gameUpdate mixes frame orchestration with mining rules, placing rules and inventory click handling. Extract the pure rule blocks into session/actions/. Do this after the render split; it is the riskier of the two.

Measure before optimising

There is currently no way to know what a real iPad is doing. A small dev overlay — frame time, draw calls, active liquid cells, dirty light columns — turns performance work from guesswork into measurement. Chunked terrain caching is the standard fix for the per-tile drawImage cost, but it adds a whole invalidation bug class: do not do it speculatively.

12 Roadmap — correctness

  • Item loss on a full inventory. tryBucket removes the bucket then adds the filled one; with all 32 slots full and two stacked buckets, the result is destroyed. A swapItem helper that verifies space first would close the whole class.
  • Partial-success returns. transferSlot can move some items and still return false. Callers reading that as "nothing happened" will be wrong.
  • Save integrity. No version field or checksum on the payload; a truncated write fails at parse time. A schema field plus a guarded load turns a crash into "that world could not be read".
  • player.burning decay sits in the hunger else branch, which is unrelated. No visible effect today — tidy it when that function is next touched, not before.

13 Roadmap — gameplay

  • Cheats system shipped — master toggle plus per-cheat switches; icons appear only when both are on.
  • Tree felling next — walking into a tree stops the character dead, which reads as being stuck rather than as an obstacle. Chopping the base should fell trunk and canopy.
  • Farming — seeds, tilled dirt, crops that grow over day cycles. Gives a child a reason to come back to a place they built.
  • Animal husbandry — rabbits already wander; feeding, following, breeding and a fenced pen would make critters a project rather than scenery.
  • Signs — one of the most-used blocks in this genre. Needs an on-screen keyboard path for iPad.
  • More weather — snowfall in snow biomes, thunder, fog. Cheap, and adds a lot of atmosphere.

14 Roadmap — blocks, items, mobs

Blocks

  • Coloured wool / clay — the single biggest win for creative building
  • Stone bricks, smooth stone
  • Fence and gate — pens, balconies
  • Stairs / slabs — needs sub-tile collision; big job, big payoff
  • Flowers, tall grass, cactus, vines
  • Ice, sandstone, gravel, obsidian
  • Glowstone — a bright emitter that is not a torch
  • Lever, pressure plate — door automation without full circuits

Items

  • Shears — saplings, wool
  • Fishing rod — slow and calm, well suited to the audience
  • Compass — "which way is home" is a real child problem
  • Armour, bow, diamond tier
  • Paint bucket — recolour blocks in place

Mobs

  • Sheep, pig, chicken — fits the existing critter code
  • Fish — water is currently lifeless
  • Bees, cave bats, a rare deep creature

15 Instant builds shipped

Pick a structure, tap the world, it appears — gated behind the cheats toggles so it never intrudes on ordinary play.

A prefab is data, not code: a character grid, a legend, and a bottom-centre anchor. A space leaves the existing tile alone; a dot forces air.

{
  id: 'cosy-cottage',
  name: 'Cosy Cottage',
  group: 'Homes',
  legend: { P: BLOCK.PLANKS, G: BLOCK.GLASS, D: BLOCK.DOOR, ... },
  rows: [
    '   PPP   ',
    '  PPPPP  ',
    ' PPPPPPP ',
    'PPPPPPPPP',
    'P.G...G.P',
    'P...L...P',
    'D......BP',
    'PPPPPPPPP',
  ],
}

Placement is pure logic in world/prefab.js: it wraps at the world seam, refuses to overwrite bedrock, respects the sky limit, and returns an undo record so a misplaced house can be taken back.

Eight structures ship across Homes (Starter Hut, Cosy Cottage, Treehouse), Fun (Fountain, Swimming Pool, Campfire Circle) and Landmarks (Watchtower, Bridge). Two rules earned by getting them wrong the first time: a door belongs in a side wall at floor level — in a side-on cross-section a door in the middle of the floor reads as a hole — and every enclosed room carries its own light, or it renders as a black box and looks broken.

Cheats worth adding next

  • Give items — a block palette outside Creative mode
  • Teleport home — the lost-child problem
  • Set time of day, no hostiles — a calm switch for a nervous player
  • Instant mine, fly outside Creative, reveal map
